## Decisions Made

- **Reconciliation at the transaction level, not per-caller checks** — the audit's malformed-custom-guest-ITP example flows through `copy_custom_guest_itp` (already narrow, return-None pinned by 3 unit tests in `test_itp_helpers_custom_guest.py`). Making the helper raise would break pinned contracts; ~15 scattered caller checks would miss detection-gap warning paths. The single post-staging invariant (model: `assert_itp_completeness`, re-implemented — never importing test code into production) closes all paths.
- **`ValueError` from the reconciliation, bare `raise` of `(OSError, ValueError)` from staging** — both ride the existing `except (OSError, ValueError)` at `pipeline.py:1006`. `RuntimeError` was explicitly rejected: it bypasses the typed catch, hits `main.py`'s broad catch (still exit 1 but loses the `[PROGRESS] Export step failed:` line).
- **Preserved contracts:** `copy_custom_guest_itp` return-None, `_copy_hydrate_guest_itp` FileNotFoundError→warn (:193), sibling narrow FileNotFoundError warns (:468, :543) and detection-gap warnings — untouched; pinned by `test_hydrate_guest_missing_source_still_returns_none`.
- **ion.itp needs no special case** in the reconciliation (unlike the test helper): when the `.top` includes it, `write_ion_itp` already wrote it into the same output dir.
- No GUI impact: `copy_itp_files_for_structure` is CLI-only (sole production importer `pipeline.py:882`); `quickice/gui/` untouched.
