However, the audit's *headline scenario* (malformed custom-guest ITP → partial export) flows through `copy_custom_guest_itp`, which is **already narrow and returns `None` by tested contract** — its callers then silently skip. Narrowing only the 4 broad catches therefore does NOT close the audit's own example; the fix needs either caller-side required-checks or (recommended, ~10 lines) a post-staging reconciliation that verifies every `#include`'d ITP exists in the output dir. A proven implementation of exactly that invariant already exists as the test helper `assert_itp_completeness` (`tests/e2e_export_helpers.py:490-516`).

For Finding 2, empirical benchmarking shows the current loop is far worse than the audit estimated: **~117 s** at the 10,000-row CSV cap (not "multi-second"), vs **11 ms** for a `cKDTree.count_neighbors` self-query — and `count_neighbors` handles the adversarial all-identical-points case in 0.00 s with O(1) memory where `pdist` costs a verified **400 MB** and `query_pairs` would materialize a ~50M-element set. The subtleties the replacement must respect (all verified in-env): `cKDTree` raises `ValueError` on NaN/Inf input (the CSV parser at `pipeline.py:307` uses `float()`, which accepts `"nan"` — a filter is REQUIRED), `count_neighbors` counts `n + 2·K` so `K = (count − n) // 2`, and the KDTree radius is boundary-inclusive (`<=`) vs the loop's strict `<` (measure-zero for real data). Existing scancode tests pin the warning semantics: aggregated single warning, `"possible overlap"`, and the literal `"1 of 3"` count format.

Finding 3 is a two-token fix: the except clause at `:338` currently has **no `as e` binding**, so the fix is `except (IndexError, ValueError) as e:` + `raise ... from e`. No test pins the chain.

**Primary recommendation:** Three surgical fixes in three disjoint files (fully parallelizable, but commit atomically in sequence): (1) narrow the 4 broad catches to `(OSError, ValueError)` AND add the `#include`→staged-file reconciliation in `_run_export_step`; (2) replace the SUsp-06 double loop with a finite-filtered `cKDTree.count_neighbors` self-query, lazy-imported, message format byte-identical; (3) add `as e` + `from e` at `hydrate_generator.py:338-339`.

### Fix 2 — O(n²) COM-COM overlap vectorization (SUSP-06 path)

**Chosen approach:** `cKDTree.count_neighbors` self-query with a finite-row filter, function-level lazy import (module convention), byte-identical warning message. See "Implementation Details" for the exact replacement block.

**Why `count_neighbors` (all verified empirically in-env, 2026-10-16):**

| Candidate | n=10,000 time | Memory | Verdict |
|---|---|---|---|
| Current double loop | **116.95 s** | O(n) | the problem |
| `scipy.spatial.distance.pdist` | ~0.4 s | **400 MB** transient (49,995,000 float64 — measured via tracemalloc) | Rejected: 400 MB for a warning |
| `cKDTree.query_pairs(r)` | 31 ms | O(K) set; **adversarial 10k-identical-points CSV → ~50M pair tuples → GBs** | Rejected: plausible bad-CSV OOM |
| `cKDTree.count_neighbors(self, r)` | **11 ms** | **O(1)**; adversarial case **0.00 s** | ✅ Chosen |
| Per-row numpy broadcast (loop i, vectorized vs rest) | est. 0.5–2 s | O(n) | Viable fallback, but slower and diverges from codebase cKDTree precedent |

The pair *identity* is never needed — the warning is aggregated (`n_close_pairs` of `total_pairs`; no per-pair indices in the message, verified against scancode tests). All three methods produced **identical counts** on random fixtures (243 @ n=2000, 5361 @ n=10000).

**Semantics preserved exactly:** current loop = strict `<`, Euclidean, NaN-containing pairs never "close" (`nan < ms` is False). `count_neighbors` radius is inclusive (`<= r`) — a boundary change that is measure-zero for user CSV data and unpinned by any test; document in a comment. Option for strict-`<` purists: `r=np.nextafter(ms, -inf)` — not recommended (KDTree distance computation differs from `np.linalg.norm` in last ULP anyway, so "bit-exact" is illusory).

**Alternatives rejected:** `query_ball_tree` self-query (same adversarial set blowup as `query_pairs`); chunked `pdist` (more code, still O(n²)/chunk compute, no advantage); leaving the loop (117 s at cap ≈ 2 min CLI stall on a *warning*).

Replacement block (lazy import per module convention at `:34-39`/`:411`/`:532`/`:872`):

```python
        if n_molecules >= 2:
            com_arr = np.array(positions, dtype=np.float64)
            # Lazy import (AGENTS.md): scipy is heavy — never at module top.
            from scipy.spatial import cKDTree
            # cKDTree requires finite data; CSV float() accepts 'nan'/'inf'
            # (pipeline.py _parse_positions_csv). Non-finite rows were never
            # "close" under the old loop (nan/inf < min_sep is False), so
            # filtering them out preserves semantics exactly.
            finite = com_arr[np.isfinite(com_arr).all(axis=1)]
            tree = cKDTree(finite)
            # count_neighbors on the same tree = n_finite self-pairs + 2 x
            # unordered close pairs (verified empirically, scipy 1.17.1).
            # NOTE: radius is inclusive (d <= r) vs the old strict '<' —
            # measure-zero difference for real data.
            n_close_pairs = (
                tree.count_neighbors(tree, self.config.min_separation) - len(finite)
            ) // 2
            if n_close_pairs > 0:
                total_pairs = n_molecules * (n_molecules - 1) // 2  # denominates ALL placements (incl. non-finite) — matches old message
                logger.warning(
                    "place_custom: %d of %d molecule pair(s) have COM-COM "
                    "distance < %.3f nm (min_separation) — possible overlap "
                    "(placement proceeds; no overlap check is performed)",
                    n_close_pairs, total_pairs, self.config.min_separation,
                )
```

**Edge behavior (all verified by running scipy 1.17.1 in-env):**
- Empty `finite` subset (all rows NaN): `cKDTree((0,3))` constructs fine, `count_neighbors` → 0 → `(0-0)//2 = 0` → no warning. Single finite row: `(1-1)//2 = 0`. **No special guards needed.**
- Formula check: 3 points, 1 close pair → count=5, `(5-3)//2=1` ✓; all-pairs radius → count=9, `(9-3)//2=3` ✓.
- `self.config.min_separation` is a validated `float` in `[0.1, 1.0]` for custom mode (`types.py:984`, post_init `:1012`) — never NaN.

Inserters-return-NEW-structures (V-17) is untouched — the block only reads `positions` and emits a warning before the existing placement pipeline runs unchanged.

## Common Pitfalls

1. **Fixing only the audit's 4 sites leaves the audit's own example broken.** The malformed-custom-guest-ITP scenario flows through `copy_custom_guest_itp` (already narrow, `None`-returning, contract test-pinned) → callers silently skip. Include the reconciliation (or caller-side required-checks) or the phase goal is not met.
2. **Raising `RuntimeError` from staging would bypass `_run_export_step:1006`** (typed catch) and hit `main.py:193` broad catch — still exit 1, but the `[PROGRESS] Export step failed:` line is lost and the AGENTS.md no-broad-catch spirit is violated. Raise only `(OSError, ValueError)`-compatible types.
3. **cKDTree NaN/Inf rejection:** `ValueError: data must be finite, check for nan or inf values` (verified). CLI CSV parsing uses `float()` (`pipeline.py:307`) which accepts `"nan"`/`"inf"` — without the `np.isfinite` mask, the fixed code would *newly crash* on inputs the old loop tolerated (nan < ms = False). The filter is semantically exact, not defensive sugar.
4. **`count_neighbors` self-pair formula:** returns `n_finite + 2·K`. Forgetting the `- n` or the `// 2` silently misreports the pair count in the warning; scancode tests pin the `"1 of 3"` format and would catch wrong counts only if pairs overlap in their tiny fixtures — add the explicit brute-force equivalence test.
5. **Boundary semantics:** KDTree radius is inclusive (`<= r`), old loop strict `<`. Measure-zero in practice, unpinned by tests; document in a comment rather than contorting with `np.nextafter`.
6. **`total_pairs` denominator:** keep `n_molecules*(n_molecules-1)//2` over ALL placements (including any non-finite rows) — the message format "K of N" is test-pinned (`"1 of 3"`); computing N over the *finite subset* would change the message for NaN-containing inputs.
7. **Adversarial memory traps:** `pdist` = 400 MB at the 10k cap (measured); `query_pairs` = GBs if a degenerate CSV places 10k molecules at one point (50M-pair set) — `count_neighbors` is the only O(1)-memory option. Don't choose the API by "it looks simpler."
8. **Don't break the three pinned `copy_custom_guest_itp` unit tests** (transform success, missing→`None`, name-too-long→`None`) — keep the helper's contract; harden at the transaction level (reconciliation), not by re-contracting the helper.
9. **Warning-only path stays warning-only:** the vectorization must not add rejection semantics (test `test_overlapping_placement_not_rejected` pins placement-proceeds). The AGENTS.md conditional-cKDTree-rebuild constraint is *not* implicated — don't cargo-cult success-gated-rebuild scaffolding into a one-shot query.
10. **Scipy at module import would violate the lazy-import invariant** — commits d1f99ac9/060e8d7f established scipy/genice2 deferral-to-first-use for GUI/CLI startup cost (~0.25 s). Import inside the `if n_molecules >= 2:` block (cheapest: pays only when needed).
11. **GUI broad catches are permitted** (`AGENTS.md`: GUI user-facing workflows) — `hydrate_export.py:363` stays as-is; the CLI fix must NOT "fix" GUI catches.
12. **No test breakage expected from the narrowing:** grep-verified that no test pins `"Failed to copy"`, `"Failed to generate ion"`, `"Hydrate guest ITP file not found"`, or `"Solute liquid ITP not found"` messages, and no test monkeypatches staging failures (all `write_ion_itp`/`shutil.copy` test usages are success-path). The routing/e2e tests use valid fixtures → unaffected.
13. **Timing gates must be generous** in the perf test (CI jitter): the scorer-perf precedent (`tests/test_scorer_performance.py`) uses equivalence + memory assertions (tracemalloc), not tight wall-clocks. Suggest ceiling ≥ 10× the expected post-fix runtime.
