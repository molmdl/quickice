## Decisions Made

- **`count_neighbors` self-pair formula:** `tree.count_neighbors(tree, r)` returns `n_finite + 2·K` (self-pairs + both directions of each unordered close pair; verified on scipy 1.17.1), so `K = (count − n_finite) // 2`. Empty/singleton finite subsets need no guards (`(0−0)//2 = 0`, `(1−1)//2 = 0`).
- **`np.isfinite` filter is semantically REQUIRED:** the CLI CSV parser's `float()` accepts "nan"/"inf" (`pipeline.py:307`); `cKDTree` raises `ValueError: data must be finite`. Without the filter the fixed scan would newly crash on inputs the old loop tolerated (nan/inf < min_sep is False). The filter protects the SCAN tree only — the pre-existing downstream `_remove_overlapping_water` cKDTree over placed atoms (:532-534) still raises for NaN/Inf COMs in both states (out of scope, documented in the test docstring).
- **Inclusive radius accepted and pinned:** KDTree radius is `d <= r` vs the old strict `<` — measure-zero for continuous CSV data; pinned at a dyadic exact-boundary fixture. `np.nextafter` contortion rejected (KDTree distances differ from `np.linalg.norm` in the last ULP; "bit-exact" is illusory per research).
- **`count_neighbors` chosen over `pdist`/`query_pairs`:** pair identity is never needed (aggregated warning); `pdist` costs 400 MB transient at n=10k, `query_pairs` materializes ~50M tuples on adversarial all-identical inputs — only `count_neighbors` is O(1) memory.
- **Tests committed WITH the fix** (single atomic commit): the 30 s perf ceiling is RED pre-fix (118.54 s breach), so separate test-only and fix commits would leave an intermediate red commit — plan explicitly prescribed the single atomic landing.
