## D1 — Custom-molecule export residue naming → **option-a: Fix the flow**

**Chosen:** The dialog's proceed path must actually reconcile names so the
structure's residues and the emitted `.top` moleculetype name agree for the
liquid custom molecule. `assert_gro_top_consistent` is used STRICTLY (no
fallback recipe) for the unrenamed-upload scenario after the user clicks
"Yes".

**Rationale (one paragraph):** Making "a passing e2e = a real pass" literally
true was worth the small production change: the strict gro/top gate becomes
usable unconditionally on the custom path for realistic unrenamed uploads
(the exact UAT Issue 2 input class), so 48.3-13/14 can assert the strongest
invariant instead of a documented fallback. The minimal-risk reconciliation
site is the INSERTION boundary (`CustomMoleculeInserter`), not the panel and
not the writers: the dialog's "No" path blocks progress entirely, so by
insertion time the ITP `[moleculetype]` name is the accepted name; the
inserter already parses the ITP (for charge), and fixing it there fixes the
GUI worker, the CLI pipeline, and direct API use uniformly — with zero
changes to `quickice/cli/pipeline.py` and zero mutation of user files.

**Implemented (48.3-02):** `CustomMoleculeInserter` registers the custom
molecule under the ITP `[moleculetype]` name when usable as a GRO residue
name (≤5 chars, not reserved); otherwise falls back to the registry default
`"MOL"` (pre-fix behavior) with a logged warning. For ITP names >5 chars
strict gro/top agreement is impossible in `.gro` format (5-char residue
limit) — grompp remains the authority there; for reserved names (e.g.
`SOL`) the fallback also applies. Known residual edge: registry name
collision (same inserter instance reused) yields a suffixed name
(`etoh_1`) in `.gro` vs the unsuffixed ITP name in `.top` — same mismatch
class as pre-fix (`MOL_1`), unchanged severity, grompp still passes.

**Downstream implications:**

| Plan | Must use |
| ---- | -------- |
| 48.3-07 (GAP-8 CLI mixed-guest) | Unaffected by D1 (hydrate-guest staging path, not `CustomMoleculeInserter`). |
| 48.3-13 (MainWindow fullchain GUI e2e) | Assert `assert_gro_top_consistent` STRICTLY on the custom-molecule export, including the unrenamed-upload + dialog-"Yes" flow. The proceed-path export passes it (proven by `tests/test_custom_molecule_residue_reconciliation.py`). No grompp-only fallback recipe needed. |
| 48.3-14 (G2 collision GUI e2e) | Same strict invariant. If the scenario also exercises >5-char ITP names, that sub-case must use grompp rc==0 + atom-count parity (strict agreement impossible in `.gro` for such names) — document it inline if used. |

**Test evidence:** `tests/test_custom_molecule_residue_reconciliation.py`
(2 headless tests, offscreen + dialog-mock pattern per 48.3-03): proceed
path → `moleculetype_name == "etoh"` → export passes

`MOL` residue; reject path still blocks generation.

## D2 — Mixed built-in (CH4+THF) `--cage-guest` CLI export → **option-a: Pin and document**

**Chosen:** Pin the limitation with one cheap explicit test + docstring;
do NOT declare it out of scope.

**Rationale (one paragraph):** The CLI `write_interface_*` writers carry a
single guest stream (`detect_guest_type_from_atoms` picks ONE guest type),
so mixed built-in hydrates exported through the CLI path silently stage
only one guest ITP — a design limitation, not a bug (GUI multi-molecule
writers are the mixed-coverage path; 45-RESEARCH recommended GUI-only).
An explicit pin test pre-answers the inevitable "why did THF disappear"
confusion AND catches a silent regression of the limitation (e.g. someone
changing single-stream writer behavior would flip the pin test). The
cons is documentation hygiene, solved by a docstring that frames the
assertion as a LIMITATION pin, not an endorsement.

**Downstream implications:**

| Plan | Must do |
| ---- | -------- |
| 48.3-07 Task 3 | IMPLEMENTS the pin test: assert single-guest output through the CLI interface-writer path (one guest ITP staged / one guest moleculetype in `[molecules]`) with a docstring that (a) states the single-guest-stream design limitation, (b) cross-references the GUI-only mixed coverage (`tests/test_e2e_mixed_lattice_gui.py` + 48.3-05's `test_mixed_interface_*` files). Never write a test EXPECTING mixed `[molecules]` output through the CLI interface writers — it fails by design. |

**No implementation in 48.3-02** for D2 (per decision; the pin test belongs
to 48.3-07 Task 3).
