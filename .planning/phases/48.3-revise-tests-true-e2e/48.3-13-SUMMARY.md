## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] patch_gui_modals mis-routed QFileDialog return_value (method mock returned under a class-sounding name)**

- **Found during:** Task 2 verification (all 4 export cases failed "expected 'Export Complete' dialog"; no traceback, no critical — exports silently returned False at `if not filepath`)
- **Issue:** `patch.object(export_mod.QFileDialog, "getSaveFileName")` returns the METHOD mock; the helper exposed it as `export_file_dialog`, so tests setting `.getSaveFileName.return_value` configured a child attribute of the method mock and the real call kept returning the default `("", "")` → exporter's silent `return False`
- **Fix:** patch the whole `QFileDialog` class in the export module's namespace (`patch.object(export_mod, "QFileDialog")`), configure `getSaveFileName.return_value` on it; docstrings updated to match
- **Files modified:** tests/gui_e2e_helpers.py
- **Verification:** all 9 file tests green 2× consecutively; GATE-SUBSET 456 passed / 0 failed after the fix
- **Committed in:** ce7065e2

**2. [Rule 1 - Bug] Plan's teardown spec would crash on `_custom_worker` (QObject has no `wait()`)**

- **Found during:** Task 1 implementation
- **Issue:** plan text (and research §3 Blocker-4 wording) says `.wait(5000)` for `_hydrate_worker`, `_ion_worker`, `_custom_worker` — but `CustomMoleculeWorker` is a plain QObject moved into `_custom_worker_thread` (custom_molecule_worker.py:18), so `wait()` would raise AttributeError
- **Fix:** `teardown_threads` calls `wait(5000)` only on `isinstance(worker, QThread)` (`_hydrate_worker`, `_ion_worker`); the custom worker's lifetime is covered by `quit()+wait()` on its hosting thread `_custom_worker_thread`
- **Files modified:** tests/gui_e2e_helpers.py
- **Verification:** file green 2×, no "QThread: Destroyed" on stderr, clean exit 0
- **Committed in:** 4728d380
