## Decisions Made
- **Resource paths anchored to the quickice package, not file-depth arithmetic.** The plan's "zero import edits" truth held for imports but NOT for `__file__`-relative resource paths: `test_chain_structures.py`'s `DATA_DIR = Path(__file__).resolve().parent.parent / "quickice"/"data"/"custom"` broke outright (8 failures — resolved to `tests/e2e/quickice/...` from the new home), and both grompp files' `gmx_workspace` fixture silently redirected the persistent debug workspace from root `tmp/e2e-gmx-validation/` into `tests/e2e/tmp/` (tests "passed" only because mkdir creates the dir). Fix: `Path(quickice.__file__).parent / "data" / "custom"` (package data lives INSIDE the package — same pattern the batch's own test_itp_baseline_data.py already uses) and `Path(quickice.__file__).resolve().parent.parent / "tmp" / "e2e-gmx-validation"` (repo root via package — scancode suite's REPO_ROOT pattern). Depth-arithmetic (`parents[3]`) was rejected: it re-breaks on the next move. **Batches B/C/D should grep their sources for `__file__` before moving — the sys.path grep in the plan template does NOT catch this class.**
- **Provenance comments refreshed to the new path rather than kept naming the old file.** 48.3-16 kept "# Ported from <deleted-file>" comments, but THIS plan's stale-reference gate greps for the old names — so gmx_validation's 2 lines naming `test_e2e_itp_baseline.py` as the current bundled-ITP coverage home now point at `tests/e2e/export_validation/test_itp_baseline_data.py`, and e2e_export_helpers' "COPIED from" note names the new path with "(pre-48.3-21 root-level version; renamed+moved by 48.3-21)" preserving full git-history traceability without matching the grep.
