## 1. Summary of Findings

The suite has **45 files matching `test_e2e_*.py`** (all in `tests/` root — none in the `tests/scancode/`, `tests/test_cli/`, `tests/test_output/` subdirectories), collecting **~400 tests**. Of these, only **24 files (~140 tests)** actually run `gmx grompp` (the authoritative "sim-ready" gate). The remaining **21 files (~260 tests)** are named "e2e" but never run grompp, never touch the GUI exporters or the CLI pipeline, or test a single stage in isolation.

**"A passing e2e" is currently NOT "a real pass of the workflow"** for four structural reasons, each of which directly allowed a UAT bug to reach manual testing:

1. **The writer-direct convention.** The grompp workhorses (`test_e2e_gmx_validation.py`, `test_e2e_gmx_param_validation.py`, `test_e2e_custom_guest_cli_grompp.py`, `test_e2e_chain_export_1/2.py`) call `quickice.output.*` writer functions DIRECTLY with structures built by `e2e_export_helpers` — bypassing the GUI exporters (`quickice/gui/export.py`), the CLI `_run_export_step`, and MainWindow. Both UAT-Issue-2 and UAT-Issue-3 bugs lived in exactly this bypassed layer (exporter ITP staging + writer molecule-count derivation) and none of the ~60 writer-direct grompp tests caught them.

2. **Fixture sanitization hides real user input.** The flagship cross-tab tests deliberately **rename the custom-molecule files from `etoh.gro/etoh.itp` to `cmet.gro/cmet.itp`** "to avoid the etoh.itp filename collision" (`test_e2e_custom_guest_cross_tab_gui.py:177-186`, `test_e2e_custom_guest_cli_grompp.py:342-364`, `test_e2e_builtin_cross_tab_regression.py:106-124`). A real user uploads the SAME ethanol file for both the cage guest and the liquid custom molecule. When the collision bug (duplicate `#include` → grompp "moleculetype etoh is redefined") shipped, every e2e test passed because the fixtures had sanitized the scenario away.

3. **The GUI middle layer is only string-tested.** The cross-tab GUI tests call the 4 exporters directly with structures built by helpers. MainWindow's tab-to-tab hand-offs (`_current_*_result` attributes, export handlers passing `hydrate_config`) are tested ONLY by **asserting substrings of the source code** (`test_hydrate_panel.py:364-408` — `assert 'hydrate_config=self._current_hydrate_config' in src`). No headless test drives `GenerationWorker`, `HydrateWorker`, `CustomMoleculeWorker`, or `IonInsertionWorker` (only `InterfaceGenerationWorker`'s error path, via the triclinic blocking test).

4. **Cross-tab matrices have holes at the exact cell that failed in UAT.** Custom cage guest × non-sI lattice was tested at the INTERFACE export only; built-in guests were tested through the full chain. The intersection — custom guest through Solute/Custom/Ion exports on a non-sI lattice with slab truncation — is UAT Issue 3 (still partially open; two fix commits + two follow-ups landed 2026-08-04→08-11, one of which **has no regression test at all** — see Gap G3).

**Primary recommendation:** Do not distribute new tests evenly. Concentrate the revision on (a) one consolidated writer+exporter+grompp chain suite that absorbs the 7 no-grompp writer files, (b) the 4 concrete missing-matrix tests (G1–G4 below), (c) a real MainWindow-level GUI smoke chain to replace source-string asserts, and (d) renaming the 10 single-stage files so "e2e" means "grompp-validated export through a real pipeline surface". Full per-file verdicts in §2; the planner can derive ~30–40 plans from the gap list alone.

## 3. Fake-E2E Patterns Found (with evidence)

**P1 — Writers-direct "established repo convention".** `test_e2e_gmx_validation.py`, `test_e2e_gmx_param_validation.py`, `test_e2e_custom_guest_cli_grompp.py`, `test_e2e_custom_guest_gui_grompp.py` (partially), and all group-C files call `quickice.output.gromacs_writer` functions directly, staging ITPs with `e2e_export_helpers._stage_itp_files` / `_stage_custom_guest_itp`. The docstrings say this openly ("follows the established repo convention (call writers directly + `_stage_itp_files` + `run_gmx_grompp`)"). This skips: GUI exporter ITP-staging logic (`export.py` — where UAT Issue 2 lived), `_run_export_step` branch selection + wrapper construction (`pipeline.py:886-929` — where hydrate-branch count derivation lived), and `copy_itp_files_for_structure`. ~60 grompp tests exercise ~0% of that layer.

**P2 — Fixture sanitization of the real user scenario.** Three files rename the custom-molecule ethanol to `cmet.gro/cmet.itp` "to avoid the etoh.itp filename collision between the cage guest (staged as MOL_H via etoh.itp) and the custom molecule" (`test_e2e_custom_guest_cross_tab_gui.py:177-186`, `test_e2e_custom_guest_cli_grompp.py:342-364`, `test_e2e_builtin_cross_tab_regression.py:106-124`). The 520ad042 commit message confirms this pattern is what let the bug ship: *"CLI avoided this by pre-renaming files to cmet.itp in the test fixture…, not by auto-rename in the exporter. GUI users can't be expected to pre-rename."* Post-fix, only unit tests (`test_uat_f_custom_guest_fixes.py`) cover `_resolve_custom_molecule_itp_name`; **no e2e test runs the same file as both cage guest and liquid custom molecule through a GUI exporter with grompp** (G2).

**P3 — No-grompp export assertions.** 21 of 45 e2e files (groups C+D plus the gen-only parts of `mixed_cage_occupancy`) validate exports by file existence + parsing only. `assert_gro_top_consistent` catches count mismatches, but only the 24 grompp files catch `[ atomtypes ]` clashes, redefinitions, box/PBC violations, and malformed ITPs.

**P4 — Source-string assertions for GUI wiring.** `test_hydrate_panel.py:364-408` "verifies" that MainWindow export handlers pass `hydrate_config=self._current_hydrate_config` by grepping the source text. This passes even if the handler reads the wrong `_current_*` attribute, catches the wrong exception, or the attribute is never set — precisely the cross-tab hand-off bugs the phase targets.

**P5 — Synthetic structures with E2E labels.** `tests/test_output/test_gromacs_export_*.py` (8 files) build 2-water/1-ethanol structures by hand and claim "E2E" in docstrings (one says "THE main E2E test"). They unit-test exporters against inputs no generator would produce.

**P6 — Single-stage files named e2e.** 10 files (group D) test one stage's internals (generation or insertion) with no export and no next-step consumption. Several are valuable regression tests (BUG-I5, 42-00, b990d151) — the fix is the name, not deletion.

**P7 — Mocked dialogs are unavoidable but exporters are invoked un-headed.** All GUI exporter tests patch `QFileDialog.getSaveFileName`/`QMessageBox` (required under offscreen). Not itself a fake pattern — but combined with P1/P4 it means the GUI *handlers and workers* (the code between "user clicks Export" and "exporter.export_x(...) runs") have zero behavioral headless coverage.

## 4. Middle-Stage Coverage Gaps (what would still reach manual testing)

Each gap: workflow stage → bug class it would catch → evidence.

**G1. Custom cage guest × non-sI lattice × downstream tabs (Solute/Custom-Molecule/Ion exports), GUI + CLI.**
Bug class: config-vs-structure molecule-count desync in downstream writers — exactly UAT Issue 3 (`.top [molecules] MOL_H 864` vs `.gro 576`; slab truncation + config-derived counts; grompp "number of coordinates does not match topology").
Evidence: `test_e2e_custom_guest_lattices_{gui,cli}.py` docstrings: "tests ONLY the interface export (not all 4 exporters)"; `test_e2e_lattice_cross_tab_{gui,cli}.py` use built-in ch4 only. Post-UAT, sII **mixed** CH4+custom got ion coverage (`test_e2e_custom_guest_mixed_cage.py`) but single-custom-guest × sII/c2te/ice1hte/16 × solute/custom/ion exports remains untested. 45-VERIFICATION also notes the CLI `_custom_result` branch was never run for non-sI lattices.

**G2. Same-basename collision e2e (cage-guest ITP and liquid custom-molecule ITP share a basename).**
Bug class: UAT Issue 2 — exporter stages both to `etoh.itp`, writers emit duplicate `#include "etoh.itp"`, grompp "moleculetype etoh is redefined" (Custom/Solute/Ion tab exports).
Evidence: every e2e that combines both tabs pre-renames to cmet (P2); only unit tests cover the rename helper. A regression in `_resolve_custom_molecule_itp_name` or in the exporters' use of `custom_molecule_itp_name` would pass the whole suite.

**G3. Mixed built-in (CH4+THF) through the INTERFACE tab export — fix shipped with NO regression test.**
Bug class: single `detect_guest_type_from_atoms` pass labels all 1296 guests CH4_H → grompp atom-count mismatch (b278a9ed, 2026-08-11). The commit touched only `guest_info.py` + `interface_writer.py` — no test file.
Evidence: grep across all e2e/output/cli tests: mixed CH4+THF exports are tested via the GUI hydrate exporter (`test_e2e_mixed_lattice_gui.py`, `test_cli/test_mixed_cage_cli.py`) and the ION exporter (`test_e2e_mixed_ion_export.py`) only; no test drives `write_interface_top_file` / `InterfaceGROMACSExporter` with a CH4+THF hydrate slab. `builtin_cross_tab_regression` builds separate ch4 and thf chains (fixture line 127: `for guest_type in ("ch4", "thf")`), never mixed.

**G4. Pocket and Piece mode exports — zero grompp coverage anywhere.**
Bug class: geometry-specific export breakage (cell/PBC shape, molecule ordering in pocket cavity or piece) reaching grompp only at user runtime.
Evidence: `grep pocket|piece` over all grompp-bearing e2e files → no hits; `test_e2e_gmx_param_validation.py` uses `_make_slab_interface` only; `test_cli_pipeline.py` runs pocket/piece workflows (`test_interface_pocket`, `test_interface_piece`, `test_pocket_mode_ion`) but its `TestPipelineGromppValidation` class has exactly 2 tests (slab interface, solute-ion chain). All 45 e2e grompp assertions are slab-shaped.

**G5. GUI middle layer: workers + MainWindow hand-offs (behavioral, headless).**
Bug class: wrong `_current_*_result` threading between Tab 0→2→3→4→5, export handler passing stale/absent `hydrate_config`, worker result mis-wiring — the "cross-tab data flow" documented in AGENTS.md as duck-typing (CP-01).
Evidence: only `InterfaceGenerationWorker`'s error path is exercised (`test_e2e_triclinic_blocking_e2e.py`). `GenerationWorker` (Tab 0), `HydrateWorker` (Tab 1, QThread), `CustomMoleculeWorker` (Tab 3), `IonInsertionWorker` (Tab 5) have no headless test; MainWindow handlers are verified by source-string grep (P4). A regression like "ion export handler reads `_current_solute_result` instead of `_current_ion_result`" passes the suite today.

**G6. Full-CLI subprocess grompp breadth.**
Bug class: breakage in the real `CLIPipeline.execute()` step sequencing / auto-chain upgrade (source→interface→custom→solute→ion) that `_run_export_step`-direct tests cannot see (45-RESEARCH Risk 8: tests using `_run_export_step` bypass the auto-upgrade logic in `_run_solute_step`/`_run_ion_step`).
Evidence: `test_cli_pipeline.py` `TestPipelineGromppValidation` = 2 grompp cases out of ~11 workflow tests; hydrate-only, hydrate+interface+ion, interface+custom+solute+ion subprocess runs assert file existence only.

**G7. Depol mode through a real export (minor).**
Bug class: depol=optimal producing a structure that fails downstream staging (low risk — 45-RESEARCH Pitfall: strict and optimal are byte-identical in GenIce2 2.2.13.1). Evidence: `test_cli/test_depol_flag.py` tests flag threading only, no grompp. LOW priority.

**G8. Hydrate tab (Tab 1) → Interface (Tab 2) hand-off via GUI worker with custom guest (minor-medium).**
Bug class: `HydrateWorker` result → `_current_hydrate_config` threading; custom-guest metadata dropped between tabs. Evidence: `HydrateWorker` untested; custom-guest metadata is threaded through exporters directly in tests. Would partially have caught UAT Issue 3's config-vs-structure split earlier (the config is tab-borne).

**G9. CLI ice-only export branch (minor).** `_run_export_step` ice branch has writers-direct coverage (`gmx_validation` ice) but no CLI-level test. LOW priority.

   - G1: extend `test_e2e_custom_guest_lattices_{gui,cli}.py` from interface-only to all downstream exports (mirror `test_e2e_custom_guest_cross_tab_*` with parametrized lattices).
