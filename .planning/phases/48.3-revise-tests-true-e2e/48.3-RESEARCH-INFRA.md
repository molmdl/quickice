## 1. Summary

The suite collects **1890 tests in 144 files** (1.44s collect). The 48.2-era folklore that shaped past plans — "GenIce2 fixtures cost ~3-5s each", "full CLI pipeline tests take 30-60s", "the full suite deadlocks ~1hr for unknown GUI/Qt/VTK reasons" — is now **measurably wrong or fully explained**:

1. **GenIce2 is cheap now.** Direct micro-benchmark: ice_ih 96-molecule generation = **17ms**; sH 2×2×2 = 60ms; sII 3×3×3 = 360ms. The "~3-5s each" claim in AGENTS.md is obsolete. Module-scoped fixture amortization is still good practice but is no longer load-bearing for runtime.
2. **The full-suite hang has a named culprit.** `tests/test_custom_molecule_panel_34_6.py` hangs at its **second test** (`test_button_state_persistence` → lazy import + instantiation of `CustomMoleculePanel`, a VTK-embedded widget) — reproduced **alone, with `QT_QPA_PLATFORM=offscreen`**. It is a C-level deadlock: pytest-timeout SIGALRM and `faulthandler` both fail to dump it (exit 124 via external `timeout`). Two other QApplication files (`test_ion_source_dropdown.py`, `test_custom_molecule_panel_34_6.py`) **segfault (core dump)** without offscreen. This fully explains every "full suite deadlocks ~1hr" report since 48.1-14: alphabetical collection reaches `test_custom_molecule_panel_34_6.py` early and pytest dies in-process.
3. **The e2e subset is a real, fast gate.** All 45 e2e files + the byte-equivalence test = **414 tests, 70.84s, 414 passed, 0 failures, 0 skips** (offscreen). Combined with scancode (306 tests, 3.3s) and CLI subprocess tests (~1.05s each), the **entire suite should run in ~4-5 minutes** once the one hanging file is fixed and offscreen is enforced — making a true full-suite gate achievable for the first time since 48.1.

**Primary recommendation:** Fix/neutralize the one hanging file + enforce `QT_QPA_PLATFORM=offscreen` at session start, then restore the **full-suite run as the 48.3 end gate**; during the revision grind, keep the proven FAST gates (collect count + path-stripped test-ID diff + targeted subsets).

## 4. Organization Proposal

### 4.1 Current layout (tests/ root = 107 test files + 4 non-collected)

```
tests/
├── conftest.py               # root: GenIce2 fixtures, gmx_skipif, run_quickice
├── e2e_export_helpers.py     # shared helper — imported via sys.path.insert hack in 54 files
├── _capture_gro_top_baseline.py  # baseline refresh script (non-collected)
├── em.mdp                    # grompp input
├── repro_*.py                # 2 non-collected repro scripts
├── test_e2e_*.py             # 45 files, 400 tests  ← the declutter target
├── ~62 other test_*.py       # ~1250 unit/regression tests
├── scancode/   (17 files, 306 tests)   # grouped in 48.2-01
├── test_cli/   (7 files, 80 tests)     # grouped in 48.2-02
└── test_output/(17 files + conftest, 140 tests)  # grouped pre-48.2
```

### 4.2 Key fragility to fix BEFORE any moves

**54 files** contain `sys.path.insert(0, str(Path(__file__)...))` hacks to import `e2e_export_helpers` (34 of the 45 e2e files, plus test_output ×7, scancode ×3, others). Every move breaks these (48.2 needed 13 edits across 7 files for just 17 moves).

**Sequencing recommendation:** first convert all `e2e_export_helpers` imports to absolute package imports —
`from tests.e2e_export_helpers import ...` — exactly mirroring the proven location-insensitive `from tests.conftest import gmx_skipif` pattern used by 26 files today (works from any depth; `tests/__init__.py` exists). Then files move with **zero path edits**, and the 54 hacks can be deleted. (`_capture_gro_top_baseline.py` keeps its own sys.path setup for direct-script mode; only its import line changes.)

### 4.3 Proposed layout (feature-organized; respects 48.2 precedent)

```
tests/
├── conftest.py                # + NEW: session-start QT_QPA_PLATFORM=offscreen guard
├── e2e_export_helpers.py      # stays (or → tests/_helpers/); imports become package-absolute
├── _capture_gro_top_baseline.py
├── em.mdp
├── test_gro_top_byte_equivalence.py   # stays at ROOT (collision rule below) or moves WITH baselines (§5.3)
├── unit/  (optional — the ~62 root unit files; low priority, fuzzy value)
├── e2e/
│   ├── chains/      # chain_export_1, chain_export_2, workflow_chains, cross_chain_invariants,
│   │                # builtin_cross_tab_regression
│   ├── hydrate/     # hydrate_generation, custom_guest_hydrate, filled_ice_cli_hydrate_grompp,
│   │                # sH_cage_occupancy, sH_cross_tab, sH_interface_export, mixed_cage_occupancy,
│   │                # same_custom_two_cages
│   ├── interface/   # ice_generation, interface_generation, mixed_interface_generation,
│   │                # ice_interface_export, triclinic_blocking_e2e, triclinic_hydrate_export
│   ├── solute_ion/  # solute_insertion, solute_export, ion_insertion, ion_export, mixed_ion_export
│   ├── custom_guest/# custom_molecule, custom_export, custom_guest_* (10 files: cli/gui grompp,

│                    # stage_custom_guest_itp, e2e_custom_molecule (if not in custom_guest/)
├── scancode/                  # unchanged
├── test_cli/                  # unchanged
└── test_output/               # unchanged
```

**Taxonomy principles (from the file inventory):**
- Group by **structure/feature domain**, NOT by gui/cli: 12+ files are cross-tab **twins** (same scenario via CLI and GUI entry, e.g. `lattice_cross_tab_cli.py`/`_gui.py`) — separating them into cli/ and gui/ dirs would tear pairs apart. Keep the `_cli`/`_gui` filename suffixes as the path discriminator.
- The byte-equivalence CONTRACT test **stays at tests/ root or moves together with its baselines** — never into a subdir whose conftest defines `custom_structure`/`solute_structure`/`ion_structure` (the 48.2-documented collision with `test_output/conftest.py`; a new `e2e/conftest.py` must not define those names either — safest: **no new conftest in e2e/** at all).
- Per-wave gates for every move wave: collect-count unchanged + path-stripped test-ID diff empty + targeted subset run (48.2 precedent, proven 3×).
- **No `__init__.py`-less risk**: subdirs already use `__init__.py` (scancode/test_cli/test_output precedent); keep it for e2e/ subdirs.

## 5. Markers & Gating

### 5.1 Current state
- Root `conftest.py` registers exactly one marker: `slow`. Used by 5 sites / **19 tests** (`-m "slow"` verified: 19 collected).
- `gmx_skipif` (26 files) = `pytest.mark.skipif` instance — no registration needed, no warnings.
- Other marks: `parametrize` (84), `skip` (2 — pytest-qt not installed, in test_solute_insertion.py:237,251), `skipif` (1 — em.mdp existence check in scancode triclinic_pbc:549).
- **No pytest config file exists** (no pytest.ini/pyproject.toml/setup.cfg/tox.ini) — pure default discovery; rootdir = project root via root conftest.py.

### 5.2 Recommended marker scheme
Register in root `conftest.py` `pytest_configure` (extend the existing function, no new config file):
- `e2e` — apply to all 45 e2e files (enables `-m e2e` / `-m "not e2e"`; alternative: rely on filename glob `tests/test_e2e_*.py` which already works — markers add class/parametrize-level granularity only if wanted)
- `gui` — tests that instantiate QApplication/VTK widgets (the 11 PySide6 files + scancode gui_ion/vtk_dup); lets a user run `pytest -m "not gui"` on a broken-display machine
- `cli` — subprocess CLI tests (~1s each; enables fast iteration via `-m "not cli"`)
- `gmx` — optional: tests that shell out to `gmx grompp` (subset of current gmx_skipif population); low priority since gmx_skipif already handles absence
- `slow` — existing 19 tests; optionally re-scope after measurement (the 4 slow CLI classes are now ~1s each, so `slow` mostly means "subprocess", overlapping with `cli`)

Practical subset selectors after registration:
- Fast inner loop: `pytest -m "not slow and not cli"` → ~1780 tests, est. ~2-3 min
- e2e gate: `pytest tests/e2e/ tests/test_gro_top_byte_equivalence.py` → 414 tests, 71s (measured)
- GUI sanity: `pytest -m gui` with offscreen → ~150 tests, seconds

### 5.3 Gating recommendation (CI-less, local runs only)
1. **FAST gates per wave (proven 48.2 pattern):** (a) collect count vs baseline, (b) path-stripped sorted test-ID diff, (c) targeted subset run of touched files.
2. **Fresh baselines required:** the 48.2 baselines (`phase48_2_before_count.txt`, `phase48_2_before_ids.txt`) lived in `/tmp/opencode/` and are **GONE** (ephemeral — verified empty). 48.3 must capture its own on day one and store them under `.planning/phases/48.3-revise-tests-true-e2e/` (committed, survives) — not /tmp.
3. **Restore the full-suite gate for the END of 48.3** (after fixing the hanging file + offscreen guard): expected ~4-5 min, run under an external `timeout` guard. This is the single highest-value change for the phase goal — it converts "targeted regression" back into "the whole suite passes", which is what "a passing e2e is a real pass" means. Never rely on pytest-timeout alone for this run (C-level hangs are SIGALRM-impervious — reconfirmed today).
4. **Byte-equivalence gate stays:** `pytest tests/test_gro_top_byte_equivalence.py` (0.6s) after any writer/output change; refresh baseline only via `tests/_capture_gro_top_baseline.py` with explicit user approval (baseline = byte contract).
