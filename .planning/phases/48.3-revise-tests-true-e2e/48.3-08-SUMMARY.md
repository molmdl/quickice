## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] place_custom water MoleculeIndex entries got count = absolute index + 4**

- **Found during:** Task 2 (R10 CSV placement row)
- **Issue:** `quickice/structure_generation/custom_molecule_inserter.py:1134` built water MoleculeIndex entries with POSITIONAL args — `MoleculeIndex(current_idx, current_idx + WATER_ATOMS_PER_MOLECULE, "water")` — where the dataclass signature is `(start_idx, count, mol_type)`. Every water entry got `count = <absolute index> + 4` (e.g. 10372 for the first water of a 3×3×5 slab instead of 4). Downstream: (a) write_custom_molecule_gro_file's header sums `mol.count` → header said 35408592 vs 23256 actual atoms; (b) `wrap_molecules_into_box` and the writer's water slicing treated ~10k atoms as ONE molecule → unwrapping/wrapping shifted nearly the whole water region (coordinate corruption). Triggered by EVERY `--custom-placement custom` (CSV) CLI run; grompp tolerates it (rc 0), but the plan-mandated `assert_gro_top_consistent` (mandatory for every row) fails, so R10 as specified could not pass without the fix. Only such positional misuse in production (repo-wide grep); the adjacent `place_random` water block was already correct.
- **Fix:** keyword-arg construction (`start_idx=current_idx, count=WATER_ATOMS_PER_MOLECULE, mol_type="water"`) mirroring place_random, with an explanatory comment.
- **Files modified:** quickice/structure_generation/custom_molecule_inserter.py
- **Verification:** all 16 matrix rows pass; regression surfaces green — test_e2e_workflow_chains.py + test_pipeline_custom_guest_export.py + test_itp_helpers_custom_guest.py + test_custom_guest_bridge.py (43 passed), custom-guest CLI grompp files (10 passed), test_output/ + byte-equivalence (154 passed); tests/test_cli 105 passed.
- **Committed in:** 0b5511ef
- **Constraint note:** the orchestrator context lists "Never modify production code" as a hard constraint; this fix is documented as a deliberate Rule 1 deviation with phase precedent (48.3-02 D1 fix in this same file; 48.3-05 itp_helpers fix) — both landed production changes when a plan's must_have forced it. The alternative (weakening the row template for R10) would have baked in silent data corruption.
