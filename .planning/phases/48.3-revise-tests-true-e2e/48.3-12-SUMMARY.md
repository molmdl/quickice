**1. [Rule 1 - Bug] Fixed .gro box-line diagonal parsing in my own test helper**

- **Found during:** Task 2 (first run of the 4 grompp legs)
- **Issue:** `_assert_gro_box_pbc_rule` initially parsed the 9-value GRO box line as row-major (`diag = values[0], values[4], values[8]`), but the writer (`_write_gro_box_vectors`, `_gro_format.py:329`) emits the GROMACS format with the three DIAGONAL elements first (`v1x v2y v3z`, then off-diagonals `v1y v1z v2x v2z v3x v3y`) — so my parse read 0.0 off-diagonal values and falsely failed all 4 legs
- **Fix:** parse `diag = box_values[:3]` for both 3-value and 9-value lines + explicit format docstring citing the writer source
- **Files modified:** tests/test_e2e_pocket_piece_grompp.py (only my new test file; production code was already correct — grompp rc=0 in the pre-write probe proved it)
