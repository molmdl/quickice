# Phase 48.3 AREA 3: CLI Pipeline E2E Coverage — Research

**Researched:** 2026-09-03
**Domain:** CLI path (`entry.py → main.py → CLIPipeline.execute()`) end-to-end test coverage
**Confidence:** HIGH (all findings verified by reading actual source/test files; runtimes measured on this machine)

## Summary

The CLI path is invoked by users as `python -m quickice [flags]` (routed by `quickice/entry.py::main()`, executed by `quickice/main.py::main()`, which delegates pipeline runs to `CLIPipeline.execute()`). A "full workflow" run is a single invocation chaining up to five computation steps — source → interface → custom → solute → ion — followed by exactly ONE export of the most-downstream structure (`ion > solute > custom > interface > hydrate > ice`, written as `{step}.gro`/`{step}.top` + staged ITPs).

Existing CLI e2e coverage splits into two disconnected halves:

1. **True subprocess e2e** (`tests/test_cli/test_cli_pipeline.py`, 30 tests via `run_quickice`): exercises the REAL user invocation path including argparse, all step methods, and export. But only **2 of 30** tests run `gmx grompp` (slab-interface; interface→solute→ion). All multi-step chain tests (including the full custom→solute→ion chain) assert **file existence only**.
2. **In-process "CLI chain" tests** (44.1-20 `test_e2e_custom_guest_cross_tab_cli.py` and its lattice-matrix siblings): grompp-validate EVERY export step — but they **bypass all CLI step methods**, building structures via direct generator calls (`HydrateStructureGenerator`, `assemble_slab`, `_insert_solutes`, `_insert_ions_from_solute`) and touching `CLIPipeline` only for `_run_export_step`. No test anywhere calls `_run_custom_step`, `_run_solute_step`, or `_run_ion_step` (only `_run_source_step` via depol threading and `_run_interface_step` via triclinic blocking).

**Measured runtime** (this machine, GROMACS 2023.5 on PATH): a full subprocess chain incl. grompp takes **~1–2 s**, not the 60–120 s claimed in stale docstrings. The entire `tests/test_cli/` directory (80 tests) runs in **107 s**. This makes a large parametrized subprocess matrix cheaply affordable. Note: the full ~1854-test suite **deadlocks** in this headless env (48.2-03 finding: GUI/Qt C-level hang) — new e2e must be CLI-only, Qt-free, and verified by targeted selection, never full-suite.

**Primary recommendation:** Build a two-tier CLI e2e architecture — **Tier A**: a parametrized subprocess prefix-matrix (each test = one legitimate user invocation truncated at a pipeline step, each output grompp-validated + species-checked via existing helpers); **Tier B**: in-process step-wiring tests calling `_run_source_step → _run_interface_step → _run_custom_step → _run_solute_step → _run_ion_step → _run_export_step` sequentially on one `CLIPipeline` instance to pin auto-chaining and attribute-propagation behavior. Total added runtime budget < 3 min.

## 1. CLI Surface Map

### 1.1 Entry routing (`quickice/entry.py::main()`, verified lines 105–201)

| Invocation | Route |
|---|---|
| no args | print help, rc 0 |
| `--help` / `-h` | argparse help, rc 0 |

| `--gui` | requires PySide6 + display; else rc 1 |
| `--cli [pipeline flags]` | strip router flags → `quickice.main::main()` |
| pipeline flags detected (any `-`-prefixed arg beyond router flags, e.g. `-T`) | implicit CLI mode → `quickice.main::main()` |
| no pipeline flags, no mode | help, rc 0 |

### 1.2 Workflow dispatch (`quickice/main.py::main()`, lines 37–46)

```python
has_pipeline_flags = (args.interface or args.hydrate or args.custom_gro is not None
                      or args.solute_type is not None or args.ion_concentration is not None)
```

- **Pipeline workflow** (any of the above): `CLIPipeline(args).execute()` — the code under test.
- **Ice-only workflow** (else): `lookup_phase → generate_candidates(n=10) → rank_candidates → print → optional --gromacs export ({phase_id}_{rank}.gro + {phase_id}.top + tip4p-ice.itp) → PDB + phase diagram`. This is a **separate code path** from CLIPipeline with **zero subprocess test coverage** of its `--gromacs` export (GAP 10).
- Broad `except Exception` at main.py:193 converts ANY unexpected exception to rc 1 + stderr message — subprocess failure tests must assert on stderr content, not tracebacks.

### 1.3 Pipeline steps (`quickice/cli/pipeline.py::execute()`, lines 154–226)

| Step | Trigger flag | Runs when |
|---|---|---|
| 0. output dir | `--output` (default `"output"`) | always; **SAFE-05**: rejects paths resolving outside CWD (pipeline.py:170–175) |
| 0b. no-overwrite | `--no-overwrite` | non-empty dir → graceful skip rc 0 |
| 1. source | `--interface` OR `--hydrate` | hydrate branch builds `HydrateConfig` (+`--cage-guest` parsing, `--depol`) → `HydrateStructureGenerator.generate()`; with `--interface` also `to_candidate()`. Ice branch (no `--hydrate`): `lookup_phase` + `generate_candidates` |
| 2. interface | `--interface` | `InterfaceConfig` from `--mode/--box-xyz/--ice-thickness/--water-thickness/--pocket-*` → `generate_interface()` |
| 3. custom | `--custom-gro` (+`--custom-itp`) | random mode (`--custom-count` or `--custom-concentration`) or CSV mode (`--custom-placement custom --custom-positions-file`); requires interface result |
| 4. solute | `--solute-type` (+`--solute-concentration`) | `--solute-source interface|custom`; **auto-chain**: upgrades `interface`→`custom` when custom result exists (pipeline.py:659–664) |
| 5. ion | `--ion-concentration` | `--ion-source interface|custom|solute`; **auto-chain**: upgrades `interface`→`solute` (or `custom`) to most-downstream result (pipeline.py:741–753); custom branch applies FIX #4 offset (ice+water+guest atom counts); solute branch duck-types solute+custom attrs onto interface |
| 6. export | always | priority `ion > solute > custom > interface > hydrate > ice`; writes `{step_name}.gro`/`{step_name}.top`; ITP staging via `copy_itp_files_for_structure` (`quickice/cli/itp_helpers.py`); hydrate branch wraps `HydrateStructure` in an `InterfaceStructure` (ice_atom_count=0) after `_validate_hydrate_atom_counts` |

**Observable behavior facts for tests:**
- Progress goes to **stderr** as `[PROGRESS] ...` lines; stdout stays clean (asserted by existing tests).
- Auto-chaining logs via `logger.info` only — **not** visible as `[PROGRESS]` on stderr. A subprocess test can only observe auto-chaining through output *content* (e.g., custom-molecule residue present in `ion.gro`).
- `--gromacs/-g` and `--no-diagram` are **no-ops for pipeline workflows** (export runs unconditionally; no diagram in the pipeline path). The 2 existing grompp tests pass them pointlessly. They matter only for the ice-only workflow.
- The `CLIPipeline` "ice" export branch (`step_name == "ice"`, pipeline.py:921–923) is **unreachable via real CLI invocation**: `_run_source_step` only runs with `--interface`/`--hydrate`, and flag-less runs are routed to the ice-only workflow in main.py. Only in-process callers could reach it.
- Custom-step input paths must be under CWD (SEC-04, pipeline.py:532–547); CSV capped at 10 000 rows (SEC-05).
- Exit codes: 0 success / 1 runtime / 2 argparse+cross-flag validation (`validate_pipeline_args`, parser.py:450–511).

### 1.4 Complete flag inventory (parser.py)

- Global: `-T/--temperature` (req), `-P/--pressure` (req), `-N/--nmolecules` (req for ice-only; forbidden with `--hydrate`; default 256 for interface), `-o/--output`, `--no-diagram`, `-g/--gromacs`, `-c/--candidate`, `--no-overwrite`, `--seed` (default 42), `--cli`, `--gui`
- Interface group: `--interface`, `--mode` (slab|pocket|piece), `--box-x/y/z`, `--ice-thickness`, `--water-thickness` (slab), `--pocket-diameter`, `--pocket-shape` (sphere|cubic)
- Hydrate group: `--hydrate`, `--lattice-type` (sI|sII|sH|c0te|c1te|c2te|ice1hte|sTprime|16|17), `--guest` (CH4|THF, deprecated), `--supercell-x/y/z`, `--cage-occupancy-small/large` (deprecated), `--cage-guest KEY=GUEST:OCC` (repeatable; **built-in guests only** — custom-guest CLI deferred by design, pipeline.py:99–107), `--depol` (strict|optimal)
- Custom group: `--custom-gro`, `--custom-itp`, `--custom-placement` (random|custom), `--custom-count`, `--custom-concentration`, `--custom-positions-file`
- Solute group: `--solute-type` (CH4|THF), `--solute-concentration`, `--solute-source` (interface|custom)
- Ion group: `--ion-concentration`, `--ion-source` (interface|custom|solute)

### 1.5 What a user's "full workflow" looks like

```bash
# (a) ice-only
python -m quickice -T 250 -P 0.1 -N 96 [--gromacs] [-o out]
# (b) hydrate-only
python -m quickice -T 270 -P 0.1 --hydrate --lattice-type sI --guest CH4 -o out
# (c) interface
python -m quickice -T 270 -P 0.1 --interface --mode slab --box-x 3 --box-y 3 --box-z 5 \
    --ice-thickness 1.5 --water-thickness 2.0 -o out
# (d) full chain (interface → custom → solute → ion), one export at end
python -m quickice -T 270 -P 0.1 --interface --mode slab --box-x 3 --box-y 3 --box-z 5 \
    --ice-thickness 1.5 --water-thickness 2.0 \
    --custom-gro mol.gro --custom-itp mol.itp --custom-placement random --custom-count 3 \
    --solute-type CH4 --solute-concentration 0.5 \
    --ion-concentration 0.15 -o out      # → ion.gro / ion.top / ion.itp / etoh.itp / ch4_liquid.itp / tip4p-ice.itp
# (e) hydrate → interface → downstream
python -m quickice -T 270 -P 0.1 --hydrate --lattice-type sI --guest CH4 \
    --interface --mode slab ... --solute-type CH4 --solute-concentration 0.5 -o out
```

Every prefix of (d)/(e) is a legitimate user invocation — this is the basis for the recommended prefix-matrix (§5).

## 3. Gap List

Each gap: missing transition → bug class it would catch → evidence.

**GAP 1 — CLI step wiring never e2e-tested (highest priority).**
Missing: no test drives `_run_source_step → _run_interface_step → _run_custom_step → _run_solute_step → _run_ion_step` on one `CLIPipeline` (and no subprocess test grompp-validates a multi-step chain beyond solute-ion). Bug class: arg→config threading regressions (wrong `getattr` defaults, `HydrateConfig`/`InterfaceConfig` field mismatches), attribute propagation breakage between steps, auto-chain regressions — all currently invisible to in-process tests and only observable as manual-test failures. Evidence: repo-wide grep — step methods referenced only by `test_depol_flag.py` (`_run_source_step`) and `test_e2e_triclinic_blocking_e2e.py` (`_run_interface_step`); `execute()` in-process only in scancode robustness tests; 44.1-20 fixture (lines 72–152) builds the chain via direct generator calls.

**GAP 2 — Custom step through CLI subprocess is never grompp-validated.**
Missing: `interface→custom→…` run where the custom-containing output passes `gmx grompp` via the real CLI. The only full-chain-with-custom subprocess test (`test_interface_custom_solute_ion`, test_cli_pipeline.py:416–446) asserts file existence + ITP count. Bug class: `write_custom_molecule_*` output errors, `etoh.itp` staging via `copy_itp_files_for_structure` custom branch, `_L`-suffix moleculetype naming, custom atom-count arithmetic — exactly the class 44.1 found in the GUI path. Evidence: `TestPipelineGromppValidation` has exactly 2 tests, neither passes `--custom-gro`.

**GAP 3 — `--custom-placement custom` (CSV positions) has no happy-path test at all.**
Missing: any CLI run (or in-process step run) with a valid positions CSV. Only the exit-2 test for a *missing* CSV exists (test_cli_pipeline.py:102–114). Bug class: `_parse_positions_csv` parsing (6-column rows, comments, row cap), `place_custom` wiring, SEC-04 containment false-positives on valid relative paths. Evidence: repo grep for `custom-positions-file` → only that validation test; pipeline.py:594–612 CSV branch untested through CLI.

**GAP 4 — `--custom-concentration` (count derived from concentration) has no happy-path CLI test.**
Missing: CLI custom step driven by concentration instead of `--custom-count`. Bug class: count calculation (`water_nmolecules × WATER_VOLUME_NM3 × 1e-24 × AVOGADRO`, pipeline.py:565–572), off-by-rounding, count=0 edge. Evidence: repo grep — `--custom-concentration` appears only in the mutual-exclusion exit-2 test.

**GAP 5 — Ion-from-CUSTOM variant never tested through the CLI.**
Missing: `interface→custom→ion` (explicit `--ion-source custom` OR auto-chain upgrade to custom). Bug class: FIX #4 offset arithmetic (slicing `source.positions[offset:]` with `ice+water+guest` atom counts) — wrong offsets would drop or corrupt custom molecules in the ion export; auto-chain upgrade-order bugs. Evidence: subprocess tests never combine `--custom-gro` + `--ion-concentration` without a solute step; in-process F2 chain (`test_e2e_workflow_chains.py:238`) uses direct inserters, not `_run_ion_step`'s custom branch (pipeline.py:763–793).

**GAP 6 — Solute auto-chain (implicit interface→custom upgrade) untested.**
Missing: a run with custom + solute but **no** `--solute-source` flag (default `interface` must auto-upgrade to `custom`); only explicit `--solute-source custom` is tested (`test_interface_custom_solute_ion`, `test_solute_source_custom`). Bug class: silent data loss — the exact class auto-chaining was added to prevent (custom molecules dropped from solute export). Auto-chain code (pipeline.py:659–664, 741–753) has zero direct test references ("auto-chain" appears nowhere in tests/). Evidence: grep; note ion auto-chain → solute IS implicitly covered by `test_solute_ion_chain_grompp` (no `--ion-source` given).

**GAP 7 — Hydrate-only CLI export for the default lattices (sI/sII/sH) not grompp-validated.**
Missing: `hydrate.gro`/`hydrate.top` from a plain `--hydrate` run passing grompp. In-process hydrate-branch grompp exists only for c2te/ice1hte (47-05) and c0te/c1te@4×4×4 (45-07); the default sI hydrate-only subprocess run (`test_hydrate_only`) checks files only. Bug class: hydrate→InterfaceStructure wrapper regressions (`ice_atom_count=0`, `_validate_hydrate_atom_counts`, CH4_H/THF_H residue naming) for the most common lattice. Evidence: inventory §2.1–2.2.

**GAP 8 — Mixed built-in `--cage-guest` through the CLI export path (DESIGN LIMITATION — needs a user decision, not silently a test).**
Missing: mixed built-in (CH4+THF) occupancy through CLI `_run_export_step` cannot produce a mixed `[molecules]` block today — `write_interface_*` is single-guest-stream (`detect_guest_type_from_atoms` picks ONE guest). The existing grompp test deliberately uses the multi-molecule writers instead (test_mixed_cage_cli.py:27–38). Bug class: silent single-guest export (only `CH4_H` OR `THF_H` staged). Recommendation: planner should surface to user — either (a) pin/document the CLI limitation with an explicit assertion test (e.g., assert single-guest output + document), or (b) declare mixed built-in CLI export out-of-scope (GUI-only, per 45-RESEARCH). Do NOT write a test expecting mixed output through CLI (it will fail by design).

**GAP 9 — Per-step export coverage through the real CLI (structural limitation).**
Missing: the CLI exports only the most-downstream structure per invocation; intermediate step outputs are never produced. The 44.1-20-style "export each step" coverage exists only in-process (where `_run_export_step` can be called repeatedly). For subprocess e2e, the equivalent is running each *prefix* invocation (§5). Bug class: prefix-invocation-specific regressions (e.g., a chain flag that breaks when it's the last step vs intermediate). Evidence: pipeline.py:226 (single `_run_export_step()` at end).

**GAP 10 — Ice-only workflow (`--gromacs` export, ranking, PDB/diagram) has no subprocess coverage.**
Missing: any `python -m quickice -T .. -P .. -N .. --gromacs` run asserting exported files. Bug class: main.py ice-only regressions (separate code path from CLIPipeline). Lower priority (not part of the full workflow), but cheap. Evidence: `--gromacs` appears in tests only inside the 2 pipeline grompp tests (as a no-op); `test_entry_point.py` covers routing (rc 0) only.

**Non-gap notes (verified, no action):**
- `--no-overwrite` happy skip is tested (rc 0 + stderr mention).
- Triclinic interface blocking is e2e-tested through `_run_interface_step` (45-06) + subprocess rejection in `test_integration_v35.py` (piece/ice-II rc≠0).
- `--depol` threading tested; GenIce2 strict/optimal produce identical output (Pitfall 1, test_depol_flag.py docstring) — do not assert output divergence.
- 47-05 documents the grompp box-size rule empirically: box shortest vector must be > 2×1.0 nm (em.mdp `rcoulomb=rvdw=1.0`); c2te 3×3×3 = 2.65 nm ✓, ice1hte 4×4×4 = 2.76 nm ✓, 2×2×2 fails for both.

## 5. Recommended CLI E2E Architecture + Runtime Budget

### Tier A — subprocess prefix-matrix (the "true e2e" black-box tier)

One parametrized test (or small group) invoking `run_quickice` with each legitimate user invocation prefix, asserting: rc 0 → expected files → `em.mdp` staged → `assert_itp_completeness` → `assert_gro_top_consistent` → `run_gmx_grompp` rc 0 → species assertions via `parse_top_molecules`/`parse_gro_residue_names`.

Matrix (all with `slab 3×3×5 or 3×3×8 nm` boxes ≥ 3 nm shortest vector; sI+CH4 hydrates; etoh custom where custom appears):

| # | Invocation (steps) | Status today |
|---|---|---|
| 1 | interface | ✓ grompp (existing) |
| 2 | interface+solute | file-only → upgrade |
| 3 | interface+ion | file-only → upgrade |
| 4 | interface+solute+ion | ✓ grompp (existing) |
| 5 | interface+custom | **NEW** (GAP 2) |
| 6 | interface+custom+solute (explicit `--solute-source custom`) | file-only → upgrade |
| 7 | interface+custom+solute+ion (explicit sources) | file-only → upgrade (GAP 2) |
| 8 | interface+custom+solute+ion, **no source flags** (both auto-chains) | **NEW** (GAP 6) — assert custom residue survives into ion.gro |
| 9 | interface+custom+ion (`--ion-source custom` or auto) | **NEW** (GAP 5) |
| 10 | interface+custom (CSV placement `--custom-placement custom`) | **NEW** (GAP 3) |
| 11 | interface+custom (`--custom-concentration`) | **NEW** (GAP 4) |
| 12 | hydrate-only | file-only → upgrade (GAP 7) |
| 13 | hydrate+interface | file-only → upgrade |
| 14 | hydrate+interface+solute | file-only → upgrade |
| 15 | hydrate+interface+ion | file-only → upgrade |
| 16 | ice-only `--gromacs` (optional, GAP 10) | **NEW** |

Runtime: measured 1–2 s per subprocess run incl. grompp → **~20–40 s total** for 15–16 cases. Each case uses `make_temp_output_dir()` (cwd-relative `tmp/`, SAFE-05-compatible) with `shutil.rmtree` cleanup. Move `make_temp_output_dir` into `tests/test_cli/conftest.py` or `e2e_export_helpers.py` for reuse.

Plumbing notes: do NOT pass `--gromacs/--no-diagram` on pipeline runs (no-ops; misleading). For failure-path spot checks, assert rc + stderr message content (main.py:193 swallows tracebacks).

### Tier B — in-process step-wiring tests (pin the internal hand-offs)

New test file (e.g. `tests/test_cli/test_pipeline_step_chain_e2e.py`) constructing ONE `CLIPipeline(args=SimpleNamespace(...))` with real argv-equivalent namespaces and calling the step methods sequentially:

- assert each step's rc == 0 and the `_result` attribute populated;
- **auto-chain assertions** impossible in subprocess: after solute step with `_custom_result` set, assert `pipe.args.solute_source` default resolved to `custom` source (inspect `report_progress` output or the returned `SoluteStructure` carrying custom attrs); after ion step, assert ion structure carries custom/solute attributes (duck-typed fields);
- export each intermediate structure via `_run_export_step` into per-step subdirs (the 44.1-20 `_assert_step_output` pattern) → grompp each — this gives 44.1-20-style per-step validation **with the real step wiring**;
- hydrate→interface variant exercises `_run_source_step`'s `to_candidate()` path (only partially covered today by depol threading);
- keep module-scoped where GenIce2 repeats (~1 s/run measured).

Runtime: ~30–60 s for a focused set (2–3 chains × 3–4 exports).

### Budget & scope guardrails

- Total new e2e: **< 3 min** added to a targeted run — affordable; verified against measured numbers (whole `tests/test_cli/` = 107 s).
- Do not attempt full-suite verification (deadlocks ~1 h in this headless env, 48.2-03). Verification = `pytest tests/test_cli/ -q` + touched e2e files + `pytest --collect-only` count check.
- Do not byte-compare GenIce2 output (nondeterministic); the 48.1 SHA256 contract stays on synthetic fixtures — new e2e must not weaken it.
- GAP 8 (mixed built-in CLI export) requires an explicit user decision (pin limitation vs out-of-scope) — surface in planning, don't auto-decide.
- Candidate cleanup fold-ins: dedup the `gmx_workspace` fixture (2 copies); sync the stale `--version` "4.5.0" assertion; fix stale "60–120 s" docstring runtimes in `test_cli_pipeline.py`.
